## 核心两问速答（先看这里）

| 问题 | 答案 | 关键证据 |
|---|---|---|
| **1. SKG 25S1 是否支持 PBP/PIP？** | **无据可查（倾向不支持）** | ① KTC 美国官网站内搜索 `25S1` = **0 条**，未检索到任何官方规格页/用户手册；② 零售与评测（[smzdm 2026-08-21](https://post.smzdm.com/p/awwkg3vp/)）只列 24.5"/原生240Hz(超频260)/DP1.4+HDMI2.0/色域/硬件低蓝光/支架，**未提 PBP/PIP**；③ 该机型仅 **1×HDMI + 1×DP**，PBP 需两路**同时**输入，而本机与显示器之间只有 1 根 HDMI 线，物理条件也不满足；④ PBP 只能 OSD 手动切换，无标准 DDC/CI VCP 可编程 |
| **2. ## 0. 结论摘要（TL;DR）

1. **显示器身份**：EDID 厂商 ID `SKG`(0x4D67) + 产品码 `0x2526` + 名称 `25S1`，即 **KTC 25S1**（`SKG` = Shenzhen KTC Technology Group，见 §2）。实测 EDID 与零售版 KTC 25S1 规格逐项吻合（24.5"、1080p、原生 240Hz、超频 260Hz、HDMI 2.0、FreeSync 48–240Hz）。
2. **PBP/PIP、Aspect Ratio/1:1/Just Scan、画面位置(Position)、DDC/CI、OSD 快捷键**：**未检索到任何官方规格页/用户手册/零售资料声明支持**（KTC 美国官网站内搜索 “25S1” = 0 条；中文侧仅见零售与评测，未提及上述功能）→ 对这几项统一判定为 **“无据可查”**（倾向不支持）。
3. **DDC/CI 实测**：`EnumDisplayMonitors` 得到 1 个活动 HMONITOR（`\\.\DISPLAY1`，1920×1080@260Hz，主屏 (0,0)）；`GetNumberOfPhysicalMonitorsFromHMONITOR` 返回 1；但 **`GetPhysicalMonitorsFromHMONITOR` 返回的 `hPhysicalMonitor = NULL`**（结构体描述字段被正常写入，证明编组无误）。因此 `GetMonitorCapabilities` / `GetCapabilitiesStringLength` / `CapabilitiesRequestAndCapabilitiesReply` / `GetVCPFeatureAndVCPFeatureReply` **全部无法执行**：VCP capabilities 字符串、支持 VCP 清单、0x10/0x12/0x60/0x0C/0x0E/0xDF/0xE1 当前值 **均不可得**。
4. **AMD Adrenalin**：**完整 Adrenalin 面板已安装**（AMD Software 26.1.1、`CNVersion 25.30.17.01`、`Adrenalin=True`、`RadeonSoftware.exe` 在位且进程运行），驱动注册表 `DDC2Disabled=0`、`DMMEnableDDCPolling=1`。自定义分辨率（Custom Resolution）属 Adrenalin 显示设置内建功能，本机具备入口条件，但**它属软件/驱动路线，且半宽模式会被 GPU 缩放“居中”而非左对齐**，对“左半屏”目标帮助有限（§5、§6）。
5. **GameViewer 虚拟显示适配器**：已安装、服务运行中（`GameViewerService` Running/Auto），但枚举出的 10 个虚拟显示适配器实例全部 `MODESPRUNED`、未接入桌面、无 HMONITOR、WMI 显示器列表无其条目 → **当前不占用任何显示输出**，不影响本方案（但它可被 GameViewer 随时激活出虚拟屏，属潜在干扰项）。
6. **硬件路线判定**：PBP/PIP 无据可查且必须双信号源 + OSD 手动切换；画面位置即使存在也只能整体平移画面（不能“只黑一半”）；DDC/CI 本机不可用；EDID 不承载分区能力信息 → **“右半屏黑”只能走软件路线**（应用层遮罩/窗口或窗口管理），详见 §6。

## 2. 显示器身份：SKG 25S1 = KTC 25S1

### 2.1 EDID 实测（注册表 `HKLM\SYSTEM\CurrentControlSet\Enum\DISPLAY\SKG2526\…\Device Parameters\EDID`，256 字节）

| 字段 | 实测值 | 说明 |
|---|---|---|
| 头部 | `00 FF FF FF FF FF FF 00` | 合法 EDID |
| 厂商 ID | `0x4D67` → **`SKG`** | 5-bit 三字母编码 |
| 产品代码 | `0x2526`（9510） | 对应型号名 “25S1” |
| 序列号 | 0（EDID 数字序列号）；文本序列号 `1234567890123` | 文本序列号明显为**占位符**，说明为批量 OEM/白牌写法 |
| 制造周/年 | 2026 年第 11 周 | 2026-03 前后生产 |
| EDID 版本 | 1.3 | 较老结构 + CEA 扩展承载高刷时序 |
| 视频输入 | `0x80` | 数字输入 |
| 物理尺寸 | 54 × 31 cm | 对角 **24.5"** |
| gamma / 特性位 | 2.2 / `0x2A` | — |
| 基础 DTD | 1920×1080@60Hz（148.5MHz） | 兼容基线 |
| 范围限制 | **V=48–255Hz，H=25–255kHz，maxPixelClock=600MHz** | 255Hz 上限说明 **260Hz 属超频时序** |
| 扩展块 | 1 个 CEA-861（rev 3，DTD offset 73） | 见下 |

CEA-861 扩展块（实测解析）：

- **Video Data Block**（9 个 SVD 原始字节）：`0x90 0x01 0x03 0x04 0x11 0x12 0x13 0x1F 0x3F`
  （除首项 `0x90` 外，其余对应 640×480p / 720×480p / 720p50/60 / 1080p50/60 等常规格式；`0x90` 属超出 CEA-861-F 常用 VIC 表的扩展值，本报告不对其语义作断言）
- **Audio Data Block**：2ch LPCM，32/44.1/48kHz，16/20/24bit
- **Speaker Allocation**：FL/FR（注：零售评测称该型号**无内置扬声器**，此处更可能是 HDMI 音频透传/3.5mm 输出能力声明）
- **Video Capability / Colorimetry / HDR Static Metadata** 扩展块：支持 BT.2020、HDR10 静态元数据
- **HDMI VSDB**（OUI `0x000C03`）：物理地址 `1.0.0.0`，maxTMDSclock = **340MHz**
- **HDMI Forum VSDB**（OUI `0xC45DD8`，v1）：maxTMDScharRate = **600MHz** → **HDMI 2.0（18Gbps）档**，无 FRL 字段
- **AMD FreeSync VSDB**（OUI `0x00001A`，v3）：**VRR 范围 48–240Hz**
- **CEA 内 DTD（关键）**：
  - **1920×1080@260Hz**，htotal 2040 / vtotal 1110，pixClk **588.74MHz**（← 当前桌面模式，超频时序）
  - 1920×1080@144Hz，htotal 2080 / vtotal 1157，pixClk 346.55MHz
  - **1920×1080@240Hz**，htotal 2080 / vtotal 1144，pixClk 571.15MHz（← 原生 240Hz）

> 一致性校验：`588.74MHz ÷ (2040×1110) = 260.0Hz`、`571.15MHz ÷ (2080×1144) = 240.0Hz`，与“原生 240Hz / 超频 260Hz”完全吻合。

### 2.2 `SKG` 厂商 ID 归属

公开 PnP/EDID 厂商 ID 表（hwdata `pnp.ids`）中明确记录：

```
SKG	Shenzhen KTC Technology Group
```

即 `SKG` 是 **深圳市康冠科技（KTC Technology Group）** 的 EDID 厂商 ID；而 KTC 自有零售机型通常使用 `KTC` 前缀（如 `KTC2400`、`KTC0D08` 等，见 linuxhw/EDID 仓库）。本机 `SKG2526` 属该集团同一 EDID 体系，故 **该显示器为 KTC 25S1（或同厂同方案 OEM 批次）**。

## 4. 本机只读 DDC/CI 探测（核心实验）

### 4.1 方法

`probe/ddc-probe.ps1`：PowerShell 7 + `Add-Type` 编译 C#，P/Invoke 调用：

| 模块 | 接口 | 用途 |
|---|---|---|
| `user32.dll` | `EnumDisplayMonitors` / `GetMonitorInfo` / `EnumDisplayDevices` | 枚举活动显示器与适配器 |
| `dxva2.dll` | `GetNumberOfPhysicalMonitorsFromHMONITOR`、`GetPhysicalMonitorsFromHMONITOR` | 取得物理显示器句柄 |
| `dxva2.dll` | `GetMonitorCapabilities`、`GetCapabilitiesStringLength`、`CapabilitiesRequestAndCapabilitiesReply` | 取 capabilities 字符串 / MC_CAPS 标志 |
| `dxva2.dll` | `GetVCPFeatureAndVCPFeatureReply` | 读取各 VCP 当前值/最大值（只读） |
| `dxva2.dll` | `DestroyPhysicalMonitors` | 释放句柄 |

**只读保证**：脚本中**不存在** `SetVCPFeature`、`SetMonitorBrightness`、`ChangeDisplaySettings(Ex)`、`SetDisplayConfig`、`SetMonitorDisplayAreaPosition` 等任何写接口的声明或调用；未修改分辨率/拓扑/OSD/输入源。

```
## [B] EnumDisplayMonitors -> physical monitors -> DDC/CI capabilities & VCP
  EnumDisplayMonitors ok=True  HMONITOR count = 1

  === HMONITOR #1 device=\\.\DISPLAY1  rect=(0,0)-(1920,1080)  primary=True  GetMonitorInfo=True

### 4.3 交叉验证（排除“编组错误 / 权限 / 会话”等自身原因）

`probe/ddc-diag.ps1` 专门复核：

```
## dxva2 physical-monitor handle diagnostics (READ-ONLY)

### 4.4 结论与不确定性

**结论**：在本机当前状态下，**无法通过标准 Windows API（dxva2）读取该显示器的 DDC/CI 能力**，因此：

- ❌ 取不到 VCP **capabilities 字符串**（`(prot(monitor)type(...)vcp(...)...)`）；
- ❌ 取不到**支持的 VCP code 清单**；
- ❌ 取不到任何 VCP **当前值**。

任务要求的关键 VCP 读取结果（统一为“不可得”，而非“不存在”）：

| VCP | 含义 | 本次结果 |
|---|---|---|
| 0x10 | Brightness 亮度 | 不可得（无句柄） |
| 0x12 | Contrast 对比度 | 不可得 |
| 0x60 | Input Source 输入源 | 不可得 |
| 0x0C | Horizontal Position (Phase) | 不可得 |
| 0x0E | Vertical Position (Line) | 不可得 |
| 0x20 / 0x22 | Horizontal / Vertical Position | 不可得 |
| 0xDF | VCP Version | 不可得 |
| 0xE1 / 0xE2 | 厂商自定义 | 不可得 |

**最可能的原因（按概率排序）**：

1. **显示器 OSD 中 “DDC/CI” 被关闭**（部分电竞屏提供该开关，且部分机型在“超频 260Hz / 高刷模式”下会限制 DDC 访问）；
2. **该型号固件不实现 DDC/CI**（¥400 档电竞屏常见；且本机 `WmiMonitorBrightness` 仅内置屏有实例，说明外接屏连 ACPI 亮度回退通道都没有）；
3. 线材/中间设备（HDMI 切换器、转接坞）只透传 EDID 而不透传 DDC/CI 命令 —— 但 EDID 可读、且当前是直连 HDMI，概率较低；
4. Windows 24H2 + AMD 驱动组合下的 dxva2 句柄问题（无法在本机进一步区分）。

**用户侧 30 秒复核建议**（均属“用户操作”，本报告不执行）：

- 用 ControlMyMonitor / Monitorian 等免安装小工具在**正常桌面会话**读取一次；若同样报“不支持 DDC/CI”，即可确认是显示器侧原因；
- 进 OSD 检查是否存在 `DDC/CI` 开关并确认处于“开”；
- 若换一根 HDMI 线/直连（不经扩展坞）后仍失败，可基本排除线材因素。

> 注：**即使 DDC/CI 可用，也改变不了本报告第 6 节的结论** —— DDC/CI 标准 VCP 中没有“PBP 开关”，也没有“只显示左半屏”的能力；位置类 VCP 只能整体平移画面。

## 6. 结论：硬件层能否实现“右半屏黑”

### 6.1 候选硬件手段逐项判定

| 硬件手段 | 能否产生“左半屏有内容 + 右半屏全黑” | 本机可行性 | 证据/原因 |
|---|---|---|---|
| **PBP（Picture-by-Picture）双画面** | 理论上：PBP 分屏 + 第二路输入无信号 → 另一半显示“无信号”黑底 | ❌ 不可行 | ① 无任何资料证明 KTC 25S1 支持 PBP/PIP；② PBP 需**两路同时输入**，本机只有 1 根 HDMI；③ PBP 只能 OSD 手动切换，无标准 DDC/CI VCP；④ DDC/CI 本机不可用 |
| **PIP（画中画）** | 不能（PIP 是叠加小窗，不是分区遮黑） | ❌ | 同上，且无资料支持 |
| **画面位置 Position（VCP 0x0C/0x0E/0x20/0x22 或 OSD）** | 不能 | ❌ | 位置调整是**整体平移**：向左平移会在右侧露黑，但**左侧内容同时被裁掉**；向右平移则相反。无法“保留左半、遮掉右半” |
| **Aspect Ratio / 1:1 / Just Scan** | 不能 | ❌ | 仅改变**非原生信号**的缩放/过扫描方式；原生 1080p 输入下无效，且不产生半屏遮黑 |
| **DDC/CI 指令级控制（VCP 写）** | 不能 | ❌ | 本机 DDC/CI 通道不可用；且 MCCS 标准 VCP 无“分区/PBP”码位，厂商私有码位无从发现（capabilities 字符串读不到） |
| **显示器 OSD 内“分区/护眼/阅读模式”类功能** | 不能 | ❌ | 无资料；此类功能通常只调色温/亮度，不做分区遮黑 |
| **换用带 PBP 的显示器** | 可以（但需新硬件） | 不适用 | 属采购建议，非本机能力 |

### 6.2 明确结论

> **硬件路线不可行 / 无据可查。**
>
> 依据：(1) 未检索到 KTC 25S1（SKG2526）任何官方规格/手册声明 PBP/PIP、画面位置、Aspect Ratio、分区显示或 DDC/CI 支持；(2) 该机型仅 1×HDMI + 1×DP，PBP 所需的第二路信号在本机不存在；(3) 本机 DDC/CI 实测不可用（`GetPhysicalMonitorsFromHMONITOR` 返回 NULL 句柄），无法读取 VCP capabilities，更无法用 DDC 触发任何位置/分区能力；(4) 即便上述功能存在，标准 DDC/CI 也没有“PBP 开关”或“半屏遮黑”码位，只能靠 OSD 手动操作，无法满足“快速切换”；(5) EDID 只承载时序/音频/HDR/VRR 能力，**不承载分区显示能力**，因此也无法从 EDID 推导 PBP 支持。
>
> 结论：**该外接显示器在硬件层无法实现“只显示左半屏且右半黑”**；本机内置屏同理（无外部输入、无 DDC VCP）。

### 6.3 唯一可行路线：软件方案（供 Lead 决策参考）

- **Windows 显示设置层面**：单显示器没有“把桌面限制在左半屏”的原生选项；也没有“画面偏移/位置”设置（只有分辨率、缩放、方向、HDR、刷新率）。
- **AMD 自定义分辨率层面**：可造 960×1080，但 GPU 缩放只有“全面板/保持宽高比/居中”，半宽画面会被**居中**，无法左对齐 → 不能替代遮罩方案（详见 §5.1）。
- **应用层遮罩/窗口方案**：在右半屏覆盖一个置顶、无边框、纯黑、不抢焦点的窗口（本机 100% 缩放、主屏 (0,0)-(1920,1080)，右半即 `x ∈ [960, 1920)`、`y ∈ [0, 1080)`），是**当前唯一能精确实现“左半可用、右半全黑”且可快速切换**的路径；工作区 `src/` 已有对应软件实现（本报告不评判其代码）。
- **软件方案的已知边界（与硬件无关，供验证时注意）**：
  - 独占全屏（exclusive fullscreen / FSE）游戏可能盖住置顶遮罩 → 需“无边框窗口化”或游戏内窗口模式；
  - 遮罩窗口需处理 DPI 感知（本机 100%，暂为 1:1 像素；若将来改缩放需 Per-Monitor DPI awareness）；
  - 遮罩不改变真实分辨率/刷新率，260Hz 模式不受影响（无额外模式切换闪烁）。

## 7. 不确定性清单

1. **型号归属**：`SKG2526 / 25S1` 通过 `SKG = Shenzhen KTC Technology Group` 与零售 KTC 25S1 规格双重吻合判定为 KTC 25S1 系列；但**无官方页面/手册直接确认**，且序列号为占位符（OEM/电商批次可能性存在），固件差异不可排除。
2. **DDC/CI 失败原因**：最可能是显示器 OSD 关闭或固件不支持；本报告在非管理员、只读约束下无法进一步区分，也**未安装第三方工具复核**（ControlMyMonitor 等需用户自行运行）。
3. **PBP/PIP 判定**：属“无据可查 + 物理条件不支持（单线单源）”，**不是**“已证实不支持”（缺官方手册）；若未来拿到 KTC 25S1 官方规格页/说明书，应以其为准。
4. **VCP 清单缺失**：因句柄为 NULL，本报告**没有**该显示器的 capabilities 字符串与 VCP 支持列表；任何声称“该屏支持/不支持某 VCP”的说法都缺乏本机实测依据。
5. **内置屏当前未启用**：本报告对内置屏的结论基于 EDID/WMI 与“未接入桌面”的枚举结果，未做“启用内置屏后”的实测（那将改变显示状态，超出只读约束）。
