# 02 · 软件与硬件替代方案调研（左半屏正常显示 + 右半纯黑）

> 场景：Windows 11 24H2 笔记本（AMD Radeon 880M 核显），唯一活动显示器为外接 24.5" 1920×1080@260Hz（HDMI，主屏，100% 缩放），屏幕右侧被物理遮挡。目标：在「A 全屏正常」与「B 桌面只在左半 960×1080、右半纯黑」之间**较为快捷地切换**。
> 本文只做只读调研，未修改本机任何显示设置；所有链接的访问日期均为 **2026-11-03**。CRU 本身的原理与操作见本系列第 01 篇（队友任务），本文重点回答「除 CRU 之外还有什么路」。
>
> **一句话结论**：操作系统和显卡驱动在原理上都只能"整屏缩放/居中"，**无法把桌面裁剪到屏幕左半**；能真正做到"真左对齐 + 右半黑"的只有两条路：**① 软件层（把主屏工作区设为左半 + 一个置顶点击穿透的黑色覆盖窗）**，② **显示器硬件层（PBP 左右分屏 + 第二路黑信号）**。前者快、免费、对普通窗口有效，但对独占全屏游戏/全屏视频无效；后者是唯一能约束独占全屏的路线，但要求显示器支持 PBP，且通常锁 60Hz。第三方软件里 DisplayFusion 的 Splits/Padding 最接近，但官方明确"无法约束全屏视频/游戏"，且右半并不是真黑。

## 1. Windows 自带能力：能做到什么、做不到什么

### 1.1 分辨率 + 缩放

- **分辨率**改变的是"整块显示器输出多少像素"，不是"只使用其中一块区域"。把外接屏改成 960×1080 后，显卡/显示器会把这块 960×1080 的画面**居中**放进 1920×1080 面板（"保持宽高比"/"1:1"）或**拉伸**满屏（"全屏"），结果是左右各一条黑边或画面变形，而不是"靠左、右半黑"。
- 这不是设置没找对，而是**数字输出（HDMI/DP）在驱动层没有"位置"选项**：NVIDIA 控制面板官方帮助写明，"Position（位置）"标签只对模拟电视/VGA 输出可用，**Digital (DVI/DisplayPort/HDMI) 不支持 Position**，只有 Scaling（Aspect ratio / Full-screen / No scaling / Integer scaling）与 Resize（过扫描修正）。Aspect 与 No scaling 都是**居中**，Full-screen 是**拉伸**。([NVIDIA 控制面板帮助](https://www.nvidia.com/content/Control-Panel-Help/vLatest/en-gb/mergedProjects/nvdspENG/Adjust_Desktop_Size_and_Position_-_Windows_Vista_and_Later.htm)，访问日期 2026-11-03)
- **缩放（Scale）**只放大 UI 元素（100%–500%），不改变活动像素区域，也不产生遮罩；100% 时就是 1:1，正好是用户现在的设置，帮不上忙。
- 想出现 960×1080 这个"非 EDID 模式"，需要显卡驱动自定义分辨率或 CRU/EDID 覆盖：NVIDIA 有 "Customise / Create Custom Resolution"，Intel 的最新 IGCC **已取消**自定义分辨率（只有 IGCC Beta 才有），AMD Adrenalin 也有自定义分辨率入口。([NVIDIA 自定义分辨率](https://www.nvidia.com/content/Control-Panel-Help/vLatest/en-gb/mergedProjects/nvdspENG/Manage_Custom_Resolutions_Page.htm)、[Intel 支持文章 000098340](https://www.intel.com/content/www/us/en/support/articles/000098340/graphics.html)、[AMD FAQ DH3-032](https://www.amd.com/en/resources/support-articles/faqs/DH3-032.html)，均访问日期 2026-11-03；AMD 页面本次抓取受限，仅据官方搜索入口)
- 结论：**分辨率 + 缩放只能得到"整屏缩小/居中/拉伸"，得不到"左半有效、右半黑"。**

### 1.2 显示排列

Windows 的显示模型里，每台显示器是虚拟桌面里的一个**矩形**，桌面是这些矩形的并集（虚拟屏幕）。系统要求各显示器构成一个连续区域，鼠标被限制在显示器范围内；窗口可以在显示器之间自由拖动。([About multiple display monitors](https://learn.microsoft.com/en-us/windows/win32/gdi/about-multiple-display-monitors)，访问日期 2026-11-03) 排列（拖动显示器图标）只改变**整台显示器之间的相对位置**，单显示器时没有任何可调项，也不能把一台显示器切成两块。

### 1.3 Win+P

Win+P 只有四个投影模式：仅电脑屏幕 / 复制 / 扩展 / 仅第二屏幕，作用于"整台显示器"层面。单显示器场景下基本等同于无操作（"仅电脑屏幕"会关掉外接屏），不能定义半屏区域。可以把它当作"A/B 模式"里切换外接屏开关的快捷方式，但它不解决半屏问题。

### 1.4 虚拟显示器（IDD / Miracast）

Windows 的 Indirect Display Driver（IDD）可以创建"虚拟显示器"，用于远程串流、虚拟桌面、USB 显示适配器等场景。([IDD 概览](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/indirect-display-driver-model-overview)，访问日期 2026-11-03) 但它只是**多出一块逻辑显示器**：桌面仍然 1:1 铺满物理外接屏，虚拟屏内容不会"映射"到物理屏的左半，也无法给物理屏加遮罩。Miracast 无线显示同理。

### 1.5 工作区（work area）概念

- Windows 给每台显示器维护一个 **work area**："屏幕中未被系统任务栏或应用程序桌面工具栏遮挡的部分"，用 RECT 表示；它决定了**最大化窗口、贴靠、桌面图标、对话框默认位置**等的可用区域。`SPI_GETWORKAREA` 只返回主显示器的工作区，其他显示器用 `GetMonitorInfo` 的 `rcWork` 读取。([SystemParametersInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfoa)、[GetMonitorInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmonitorinfoa)，访问日期 2026-11-03)
- `SPI_SETWORKAREA` 可以**设置**工作区："在多显示器系统中，该函数设置**包含指定矩形的那台显示器**的工作区"。也就是说，理论上可以把它设成 (0,0,960,1080)，让最大化窗口只占左半。
- **但有两个硬限制**（这也是所有"工作区方案"必须处理的）：
  1. **Explorer 会覆盖你的设置**。微软官方 KB 明确：Windows 10 起，Explorer 在收到工作区变化产生的 `WM_SETTINGCHANGE` 后，会**重新计算所有显示器的工作区**（按任务栏和 appbar 的位置），且**不考虑**应用通过 `SPI_SETWORKAREA` 做的修改，"这是设计使然（by design）"，应用改的工作区可能被覆盖。([KB4014104](https://learn.microsoft.com/en-us/previous-versions/troubleshoot/windows/win32/calling-systemparametersinfo-work-incorrectly)，访问日期 2026-11-03) 所以工具必须监听 `WM_SETTINGCHANGE`/`WM_DISPLAYCHANGE`/会话解锁/DPI 变化并**反复重设**。
  2. **工作区只是"约定"，不是"边界"**：它不会遮黑右半，壁纸/桌面图标/普通窗口仍可出现在右半；不改变鼠标可移动范围；全屏/无边框全屏程序、部分游戏、部分自绘 UI 的程序根本不读工作区（用整块 `rcMonitor`）。
- 另外，Windows 11 **任务栏固定在底部、官方不支持改到侧边**（第三方工具如 StartAllBack/ExplorerPatcher/Windhawk 可改），所以右下角的时钟、系统托盘、通知横幅会落在被遮挡的右半。([Microsoft Q&A：任务栏竖排](https://learn.microsoft.com/en-au/answers/questions/5878913/i-want-to-move-my-taskbar-to-the-left-side-vertica)，访问日期 2026-11-03)
- 通知横幅位置在 Windows 11 里**不可更改**（固定右下角）。([Microsoft Q&A：通知位置](https://learn.microsoft.com/en-us/answers/questions/4089246/why-cant-i-move-the-notification-position-from-the)，访问日期 2026-11-03)

### 1.6 为什么系统层面无法把桌面限制在单屏左半

1. **显示模型没有"子区域显示器"概念**：一个物理输出 = 一个矩形 target，DWM 按整块 target 合成；系统 API 只能设置整块显示器的模式/排列/缩放，不能声明"只使用左半"。
2. **缩放/分辨率只能居中或拉伸**：GPU 与显示器 scaler 的缩放模式都不提供"水平偏移/裁剪"（NVIDIA 官方：数字输出无 Position）。
3. **工作区是协作式约定**：它不遮黑、不拦鼠标、不管全屏程序，而且会被 Explorer 重算覆盖（KB4014104）。
4. **没有公开 API 能"裁掉"物理输出的一部分**；能实现裁剪的层次只有：应用层（自绘遮罩）、窗口管理器（约束最大化区域）、显示器 scaler（PBP/Position/裁剪型视频处理器）。

> 所以"系统设置里点几下"是做不到的；必须落到**软件（工作区+遮罩）**或**硬件（显示器 PBP / 视频处理器）**。

## 2. 第三方 / 开源软件

### 2.1 DisplayFusion（最接近的商业方案）

- **Monitor Splitting（监视器分屏）**：把一台物理显示器切成多个"虚拟监视器"，各自有任务栏、壁纸、屏保；**最大化窗口会被约束到所在分屏**，DisplayFusion 的"移动到下一台显示器"等函数也认分屏。([官方功能页](https://www.displayfusion.com/Features/MonitorSplitting)、[帮助：Monitor Splits](https://www.displayfusion.com/HelpGuide/WorkingWithMonitorSplits/)，访问日期 2026-11-03)
  - 对用户的用法：把 1920×1080 分成 2×1（左 960、右 960），**左分屏放日常窗口并最大化，右分屏壁纸设为纯黑**（分屏支持独立壁纸/纯色）。
  - **关键限制（官方原文）**："**目前无法把全屏视频或全屏游戏约束到分屏内**"（It's not currently possible to constrain full screen videos or full screen games to monitor splits）。即 A/B 切换对全屏内容无效，全屏游戏仍会铺满 1920。
  - 右半"纯黑"只是壁纸层面的黑：桌面图标、右键菜单、被手动拖过去的窗口、分屏任务栏都可能出现在右半；需要额外隐藏桌面图标/关闭右分屏任务栏才接近纯黑。
- **Monitor Padding（监视器留白）**：不创建分屏，只给显示器右侧预留 N 像素（如 500px），**只影响最大化窗口的大小**，不影响任务栏/壁纸/屏保。([帮助：Monitor Padding](https://www.displayfusion.com/HelpGuide/WorkingWithMonitorSplits/)，访问日期 2026-11-03) 这正好可以"约束最大化到左半"，但右半依然是桌面（不会变黑）。
- **Monitor Profiles（显示器配置档）**：保存分辨率/刷新率/排列，可用**热键**或标题栏按钮加载；属于 Pro 功能（免费版对比表中 Monitor Profiles 为 Pro 专属）。([Monitor Configuration](https://www.displayfusion.com/Features/MonitorConfig/)、[Free vs Pro](https://www.displayfusion.com/Compare/)，访问日期 2026-11-03)
- 价格：Steam 国区约 ¥200（Pro），有 30 天试用。([Steam 商店页](https://store.steampowered.com/app/227260/DisplayFusion/)，访问日期 2026-11-03)
- **评价**：真左对齐=⚠️（只对最大化窗口生效）；全屏=❌（官方明示）；切换速度=中（配置档加载 1–3s；分屏配置即时但需先设好）；额外硬件=无；风险=需付费、右半非真黑、全屏无效、分屏任务栏/图标需额外收拾。

### 2.2 MaxTo

- 把每台显示器切成若干**矩形区域（regions）**，"**窗口最大化时会留在某个区域内**"；支持预设、热键、按应用记忆位置。([MaxTo 文档：Regions](https://docs.maxto.net/tutorial/regions/)、[官网](https://maxto.net/)，访问日期 2026-11-03)
- 用法：左半一个区域、右半一个区域；最大化进左区域。
- 局限：**不遮黑**（右半仍是桌面），全屏游戏不受约束；付费（€19/年或 €79 买断）。
- **评价**：真左对齐=⚠️（最大化受限）；全屏=❌；切换速度=快（热键/双击）；额外硬件=无；风险=不黑、需付费、只对最大化路径生效。

### 2.3 PowerToys FancyZones

- 自定义区域布局，拖动窗口时吸附到区域，支持 `Win+方向键` 映射到区域、`Win+Ctrl+Alt+数字` 快速切换布局、`Win+PgUp/PgDn` 同区域切窗口。([FancyZones 文档](https://learn.microsoft.com/en-us/windows/powertoys/fancyzones)，访问日期 2026-11-03)
- 局限：FancyZones 是"拖放吸附"工具，**不改变最大化行为、不约束工作区、不遮黑**；把窗口最大化仍铺满整屏。
- **评价**：真左对齐=❌；全屏=❌；切换速度=快；额外硬件=无；风险=解决不了"遮黑"和"最大化"。

### 2.4 Divvy / AquaSnap 等网格工具

- Divvy（Mizage）、AquaSnap（Nurgo）等属于"窗口网格/贴靠"类工具：用热键把窗口放到预设网格（如左半、右半、四分之一），**不约束最大化、不遮黑**。
- **评价**：真左对齐=❌；全屏=❌；切换速度=快；额外硬件=无；风险=同上，只能当"摆窗口"的辅助。

### 2.5 黑幕 / 遮罩类工具

- 市面上"黑屏/遮罩"工具（Blackout、Dimmer、ScreenShade、双屏黑屏工具等）绝大多数是**整块显示器变黑/变暗**，或者是一个可移动的普通窗口，**没有"半屏 + 点击穿透 + 与工作区联动 + 热键切换"的成熟产品**。
- 少数多屏工具能做"只黑某一块显示器"（如把副屏整块涂黑），但那不是"同一块屏的右半"。Dual Monitor Tools 是开源免费的多屏工具集（Cursor 模块可限制鼠标在显示器之间移动，SwapScreen 可把窗口移到预设位置），但它**没有"限制到某显示器内某个矩形"的现成功能**。([Dual Monitor Tools](https://dualmonitortool.sourceforge.net/)，访问日期 2026-11-03)
- 结论：这一类别**没有可直接用的成品**，实际都要落到 2.6 的 AHK/自研路线。

### 2.6 AutoHotkey 现成脚本路线（workarea + 置顶黑色覆盖窗）

社区里已有大量"半屏黑幕/工作区"片段，拼起来就是一个完整工具：

1. **设置工作区**：`DllCall("SystemParametersInfo", "UInt", 0x002F, "UInt", 0, "Ptr", &RECT, "UInt", 0x02)`（SPI_SETWORKAREA + SPIF_SENDCHANGE），把主屏工作区设为 (0,0,960,1080)。AHK 官方论坛有 "Making empty space" 之类的讨论与现成代码（本次访问被 Cloudflare 拦截，链接供参考：[AHK 论坛帖](https://www.autohotkey.com/boards/viewtopic.php?p=438170)）。
2. **创建遮罩窗**：无边框、置顶（`HWND_TOPMOST`）、不激活（`WS_EX_NOACTIVATE`）、分层（`WS_EX_LAYERED`）、**点击穿透**（`WS_EX_TRANSPARENT`，或处理 `WM_NCHITTEST` 返回 `HTTRANSPARENT`），背景纯黑，覆盖 (960,0)-(1920,1080)。AHK 论坛有"置顶 + 鼠标穿透"的现成写法（[示例 1](https://www.autohotkey.com/boards/viewtopic.php?p=536361)、[示例 2](https://www.autohotkey.com/board/topic/99910-gui-click-through-options/)）。
3. **可选：把鼠标限制在左半**：`DllCall("ClipCursor", "Ptr", &RECT)` 可把光标锁进矩形；AHK 论坛有 "ClipCursor: Confining Mouse to a window" 的现成代码（[链接](https://www.autohotkey.com/boards/viewtopic.php?p=616450)）。注意 ClipCursor 是全局的、需要热键释放，游戏/远程桌面可能重置它。
4. **热键一键切换 A/B**：A 模式恢复工作区为整屏 + 隐藏遮罩窗；B 模式设置工作区 + 显示遮罩窗。可再对已最大化的窗口做一次"还原→最大化"（或 `SetWindowPos` 到工作区）让旧窗口立即贴合。
5. **事件重设**：监听 `WM_DISPLAYCHANGE`、`WM_SETTINGCHANGE`、`WM_DPICHANGED`、会话解锁、`TaskbarCreated`，重新应用工作区与遮罩（对抗 KB4014104 的 Explorer 重算）。

**实测预期（根据机制推断，需本机验证）**：切换 <0.1s、无黑屏闪烁、无需管理员权限；对浏览器/Office/资源管理器/大多数 Win32 与 UWP 窗口有效；**对独占全屏游戏无效**（覆盖窗被绕过，全屏程序直接访问显示硬件；微软 Q&A 也确认"独占全屏下其他窗口无法显示"，需改用无边框窗口模式）；对无边框全屏视频/游戏，遮罩窗能盖住右半，但等于把画面右半切掉（内容仍渲染在右半，只是看不见）。

### 2.7 显示器厂商工具（LG / Dell / BenQ / AOC / 小米等）

- 这类工具（Dell Display Manager、LG OnScreen Control、BenQ Display Pilot、AOC G-Menu、Samsung Easy Setting Box 等）主要提供：亮度/对比度/色彩、输入源切换、Easy Arrange 分屏预设、软件"屏幕分割"（本质是窗口贴靠）、部分型号的 PIP/PBP 控制。
- **是否支持 PBP 切换因型号而异**，且多数型号的 PBP 只能在显示器 OSD 里设；厂商软件能做的通常是"输入源切换/分屏预设"，不是"半屏黑幕"。
- 结论：可作为"快速切输入源/亮度"的辅助，**不能作为通用左半屏方案**；如果用户的显示器恰好是某厂商且该型号工具支持 PBP，才值得单独评估（需查该型号说明书）。

### 2.8 分辨率快切工具

| 工具 | 能力 | 备注 |
|---|---|---|
| **QRes**（开源，SourceForge） | 命令行切分辨率/色深/刷新率，可给游戏自动切换 | 老牌、轻量，[QRes](https://sourceforge.net/projects/qres/)，访问日期 2026-11-03 |

## 3. 显卡附带功能（对单屏能否把画面放左半边）

### 3.1 NVIDIA

- 缩放模式：Aspect ratio（保持比例、**居中留黑边**）、Full-screen（**拉伸**）、No scaling（原始大小、**居中**）、Integer scaling（整数倍放大，Turing 及以后、且由 GPU 缩放时可用，**居中**）。
- **Position（位置）只支持模拟电视/VGA，数字 DVI/DP/HDMI 不支持**。([NVIDIA 帮助](https://www.nvidia.com/content/Control-Panel-Help/vLatest/en-gb/mergedProjects/nvdspENG/Adjust_Desktop_Size_and_Position_-_Windows_Vista_and_Later.htm)，访问日期 2026-11-03)
- 自定义分辨率可以加 960×1080，但显示时仍按上面的缩放模式居中/拉伸。
- DSR（Dynamic Super Resolution）：以更高分辨率渲染再下采样到面板，**只影响渲染质量，不改变画面位置**，对"左半屏"无用。
- **结论：NVIDIA 无法把单屏画面靠左。**

### 3.2 AMD（本机 Radeon 880M 核显）

- Adrenalin 的显示缩放模式同样是 **Preserve aspect ratio / Full panel / Center**（保持比例居中 / 铺满拉伸 / 居中原始大小），GPU Scaling 与 Integer Scaling 都只做"缩放+居中"，没有水平偏移。([AMD FAQ DH3-019](https://www.amd.com/en/resources/support-articles/faqs/DH3-019.html)，访问日期 2026-11-03；该页本次抓取受限，据官方 FAQ 标题与通用行为)
- 自定义分辨率：Adrenalin 提供 Custom Resolution（可加 960×1080 等非标模式），但显示位置仍由缩放模式决定。([AMD FAQ DH3-032](https://www.amd.com/en/resources/support-articles/faqs/DH3-032.html)，同上)
- **VSR（Virtual Super Resolution）**：给显示器"增加"更高分辨率用于超采样，本质是渲染分辨率提升，**不是裁剪/偏移**。([AMD VSR FAQ DH3-010](https://www.amd.com/en/resources/support-articles/faqs/DH3-010.html)，同上)
- **Eyefinity**：把多台显示器合并成一个大桌面，**需要多台显示器**（单屏无法成立），对"单屏左半"无解。([AMD FAQ DH3-014：Configure Multiple Displays to Run in AMD Eyefinity Mode](https://www.amd.com/en/resources/support-articles/faqs/DH3-014.html)，同上)
- 笔记本核显还受 OEM 限制：部分机型 Adrenalin 的显示/自定义分辨率选项被裁剪，或 HDMI 输出走的是核显直连/独显直连不同路径，实际可用性需本机确认。
- **结论：AMD 同样无法把单屏画面靠左；Eyefinity 对单屏不适用。**

### 3.3 Intel（作为对照）

- Intel 显卡的缩放选项是 Scale Full Screen / Maintain Display Scaling / Maintain Aspect Ratio / Center Image，同样是"拉伸/居中"。
- 最新 Intel Graphics Command Center **没有**添加自定义分辨率的入口，只能用 IGCC Beta 或第三方工具（官方文章明确说明）。([Intel 支持文章 000098340](https://www.intel.com/content/www/us/en/support/articles/000098340/graphics.html)，访问日期 2026-11-03)

### 3.4 Integer Scaling / DSR / VSR / Surround 小结

| 功能 | 实际作用 | 对"左半屏"是否有用 |
|---|---|---|
| Integer Scaling | 低分辨率按整数倍放大、居中 | ❌ |
| DSR / VSR | 高分辨率渲染再下采样（超采样） | ❌ |
| Eyefinity / Surround | 多屏合并成一个大桌面 | ❌（单屏不成立） |
| GPU Scaling（Aspect/Full/Center） | 非原生分辨率如何填充面板 | ❌（居中或拉伸） |
| 自定义分辨率 | 增加 960×1080 等模式 | ⚠️ 只是前提，显示位置仍居中 |

### 3.5 结论

**显卡驱动层不存在"把画面放到左半、右半留黑"的能力**：数字输出没有位置调节，缩放只有"居中/拉伸"两种本质结果，Eyefinity/Surround 需要多屏。想要"左半有效"，必须在**应用层遮罩**或**显示器 scaler（PBP/裁剪）**做文章。

## 4. 显示器硬件层

### 4.1 PBP / PIP 左右分屏（唯一能约束独占全屏的路线）

**PBP（Picture by Picture）**：显示器把面板分成左右（或上下）两个窗口，每个窗口显示**一路输入信号**；OSD 里可以指定"左侧输入源/右侧输入源"（HP 显示器说明书即描述 "Set Left Side：选择显示在 PbP 画面左侧的视频输入源"，[HP 手册 c06476282.pdf](https://h10032.www1.hp.com/ctg/Manual/c06476282.pdf)，访问日期 2026-11-03；该 PDF 仅通过检索摘要核对）。PIP 则是"主画面 + 小窗"，不适合本需求。

对用户的用法与前提：

1. **前提 A：显示器支持 PBP**，且有至少 2 路视频输入（如 HDMI + DP/USB-C）。24.5" 1080p 260Hz 属于高刷电竞屏，**PBP 并不常见**（高刷型号为了带宽/成本常砍掉 PBP/PIP），必须查该型号说明书确认。
2. **前提 B：第二路输入要"有信号但显示黑色"**。如果只插一路、另一路空着，不同显示器行为不同：有的半屏保持黑、有的弹 "No Signal" 提示框、有的自动退出 PBP 回到单画面、有的自动切到有信号的输入。**要稳定得到"右半纯黑"，最稳的是给第二路喂一个黑色信号**：
   - 笔记本的第二个输出（USB-C/USB4 → HDMI/DP 转接）接显示器第二路输入，Windows 里把这块"第二显示器"的壁纸设纯黑、不放窗口；
   - 或用一台闲置设备（旧手机/迷你主机/树莓派）输出纯黑画面；
   - 或用便宜的 HDMI 测试图案发生器（输出黑场）。
3. **分辨率**：PBP 下每半是面板的一半，1920×1080 面板 → 每半 **960×1080（8:9）**。若输入仍是 1920×1080，显示器会把它缩进 960×1080 的区域：按比例缩放会出现上下黑边（有显示器说明书就写明 "PBP 模式下按正确宽高比会出现上下黑条"，[aio.lv 产品文档](https://aio.lv/document/product/985214/2200216)，访问日期 2026-11-03），拉伸则画面变形。**要填满左半且不变形，源最好输出 960×1080 的自定义分辨率**（又回到显卡自定义分辨率/CRU，见 01 篇）；ViewSonic 部分型号说明书也明确要求 PBP 时把源分辨率改成半屏分辨率（[VP3881A 手册](http://www.viewsonicglobal.com/public/products_download/user_guide/display/VP3881A/VP3881a_UG_FIN.pdf)，访问日期 2026-11-03，检索摘要）。
4. **刷新率/画质代价**：PBP 要同时处理两路输入、内部带宽要分摊，**刷新率通常被限制在 60Hz**（显示器厂商 FAQ 明确："PIP/PBP 模式下为同时处理两路信号会分配内部带宽，此时刷新率限制为 60Hz 属正常现象"，[Hansung 显示器 FAQ](https://www.superstore.co.kr/customer_center/read.html?menu=faq&wr_id=1159)，访问日期 2026-11-03）；此外 VRR/FreeSync、HDR、DSC、超频 260Hz 等大概率失效，部分型号还要求两路都接好才允许开 PBP、或提示"分辨率无法自动切到最佳"（[RS 产品手册](https://docs.rs-online.com/6d7d/A700000006573607.pdf)，访问日期 2026-11-03，检索摘要）。
5. **桌面行为**：PBP 下 Windows 看到的是一块 **960×1080 的显示器**（左半），或两块显示器（若两路都来自同一台笔记本）。所有窗口最大化、独占全屏游戏、视频全屏都被**硬件限制在左半**——这是它相对软件方案最大的优势。
6. **切换速度**：一般要按显示器摇杆进 OSD → 找到 PBP/PIP → 开关/选输入，约 2–5 秒；有的型号把"输入源"做成摇杆快捷键，但没有"PBP 一键开关"的通用设计。**DDC/CI 能否免 OSD 切 PBP 见 4.3，结论是基本不能。**
7. **额外硬件**：第二路线缆/转接器（或黑场信号源）；若两路都来自笔记本，还需要一个 USB-C→HDMI/DP 适配器。
8. **风险**：型号不支持 PBP（最常见）；PBP 锁 60Hz、失去高刷/VRR/HDR；第二路无信号时行为不可控；两路来自同一 GPU 时可能遇到 HDCP/带宽/握手问题；部分显示器 PBP 下亮度/色彩/响应时间设置受限。

**评价**：真左对齐=✅（硬件级）；全屏=✅（连独占全屏都被限制在半屏）；切换速度=中；额外硬件=需要第二路信号；风险=型号支持不确定 + 60Hz 锁 + 第二路行为不定。

### 4.2 显示器 OSD 的 Aspect / 1:1 / Just Scan / Position 能否把自定义分辨率画面靠左

- **Aspect（宽高比）/ 1:1 / Just Scan（点对点）**：这些选项决定"非原生信号如何显示"——Full/16:9 是拉伸，Aspect/Auto 是保持比例，1:1/Just Scan 是像素点对点。**它们的共同点是"居中"**：960×1080 的信号在 1920×1080 面板上，1:1 会显示成中间 960 宽的清晰画面（左右黑边），Aspect 会按比例缩放后居中，Full 会拉伸满屏。**都不会靠左。**
- **Position（水平/垂直位置）**：多数显示器的 H/V Position 只对 **VGA/模拟输入** 有效；HDMI/DP 数字输入下通常置灰或不存在（这与 NVIDIA 控制面板"数字输出无 Position"一致）。少数型号在特定模式下提供"画面位置/OSD 位置"调整，但**不能指望**用它把 960×1080 推到左边。
- 结论：**OSD 的 Aspect/1:1/Just Scan 只能决定"居中/拉伸/点对点"，不能左对齐**；Position 在数字输入上基本不可用。想要显示器侧左对齐，只有 PBP 或带裁剪的 scaler。

### 4.3 DDC/CI 能否免开 OSD 快速切换 PBP

- **DDC/CI 是什么**：通过显示线缆的 I²C 通道读写显示器的 VCP（Virtual Control Panel）功能，标准来自 VESA MCCS。常用标准 VCP 有：`0x10` 亮度、`0x12` 对比度、`0x60` 输入源、`0x14` 色彩预设等。([ControlMyMonitor 命令行参考](https://www.controlmymonitor.com/blog/controlmymonitor-command-line-reference-guide)，访问日期 2026-11-03)
- **标准 MCCS 里没有 PBP 控制项**；PBP/PIP 属于厂商私有实现，通常只有厂商私有 VCP 码，且厂商一般不公开（Dell 社区有用户请求公开 U3818DW 的 VCP/MCCS 码，[Dell 社区帖](https://www.dell.com/community/en/conversations/monitors/u3818dw-please-publish-the-vcpmccs-codes/647f7c4ff4ccf8a8deaa32df)，访问日期 2026-11-03）。因此：
  - **能做的**：用 ControlMyMonitor（NirSoft，免费）或 ClickMonitorDDC 等工具读写 VCP，实现**输入源切换、亮度/对比度调节**等；可用 `/scomma` 导出该显示器支持的 VCP 列表来探查有没有厂商私有项。
  - **基本做不到的**：**通用地**用 DDC/CI 开关 PBP。除非你的显示器型号被社区逆向出了 PBP 私有码（如某些 LG/Dell 型号），否则只能 OSD。
  - 另外，DDC/CI 在部分 USB-C 扩展坞/转接器上不可用，显示器待机/无信号时也可能不响应。
- 结论：DDC/CI 适合"快速切输入源/亮度"，**不适合作为 PBP 的通用快捷开关**。

### 4.4 HDMI/DP 切换器 / KVM

- 切换器/KVM 只是把多路信号**选一路**送给显示器，输出仍是整屏一路画面，**不产生左右分屏**，对"右半黑"无帮助。
- 唯一相关场景：配合 PBP 给第二路输入喂黑场信号时，可用切换器在"黑场源/其他源"之间切换；但这属于 PBP 方案的配件，不是独立方案。

### 4.5 外置视频处理器 / 带裁剪的 scaler（专业路线）

- 专业视频处理器/视频墙控制器（Barco、Extron、tvONE、Lumagen、Decimator、部分 LED 屏控制器等）可以对输入做 **crop（裁剪）+ scale（缩放）+ position（定位）**：把 1920×1080 输入裁出左半、放大/定位到面板左半，右半输出黑场。这在原理上能实现"真左对齐 + 右半纯黑"，且对任何内容（包括游戏）都有效。
- **代价**：设备贵（通常数千元起）、多数消费级 scaler 只到 4K30/1080p60、会引入 1–2 帧延迟、HDMI 握手/EDID 兼容问题多、无法保留 260Hz/VRR。对"260Hz 游戏 + 日常办公"的用户**不实用**。
- 视频场景的廉价替代：播放器侧裁剪/平移（如 madVR 的 zoom/pan、MPC 的 pan&scan）可以把**视频画面**移到左半，但只对播放器内视频有效，不是桌面方案。

### 4.6 不知道显示器型号时，如何判断是否支持 PBP

按成本从低到高：

1. **看铭牌/包装/系统信息**：显示器背面标签、包装箱、`ControlMyMonitor /scomma` 导出的 Monitor Name/Serial、或 Windows 设置 → 系统 → 显示 → 高级显示里的型号名。（本机 `LeftScreenMode.ini` 的注释里已记录外接屏硬件 ID 关键字为 **SKG2526**——若确为白牌/国产 24.5" 高刷型号，公开资料通常较少、PBP 支持概率偏低，优先按下面第 2、4、5 条核对。）
2. **查官方说明书/规格页**：用型号 + "PBP / PIP / Picture by Picture / PbP / MultiView / Dual Controller / 双画面 / 画中画 / 分屏" 搜索；说明书目录里通常有 "PIP/PBP" 章节。这是最可靠的方法。
3. **看接口数量**：只有 1 个视频输入（仅 HDMI 或仅 DP）的显示器**不可能**做 PBP；有 HDMI + DP（或 +USB-C）才有基础。
4. **看 OSD 菜单**：用摇杆/按键进菜单，找 "PBP / PIP / 多画面 / 输入 / Input / Multi-View / Dual Controller" 等项；有该项即支持（可顺手看它是否允许"左/右输入源"分配）。
5. **实测**：接第二路信号（另一台电脑/手机 USB-C 转 HDMI/笔记本第二个输出），看 PBP 选项是否可用、半屏是否正常、另一路拔掉时半屏是黑屏还是弹 "No Signal"。
6. **查评测**：TFTCentral、RTINGS、PCMag、B 站/知乎/CHH 的该型号评测，常会写 "PBP/PIP 支持情况" 和 "PBP 下刷新率限制"。
7. **问客服**：直接问"是否支持 PBP 左右分屏、PBP 下最高刷新率、单路输入时另一侧是否黑屏"。

## 6. 给用户的推荐组合

### 6.1 推荐主方案：自研/轻量「工作区 + 黑色遮罩」热键工具

理由：**最快（热键即时）、零成本、无额外硬件、不需要改 EDID/分辨率、可逆**；本仓库 `src/Native.cs` 已经把这套所需 API 全部封装好，补上"遮罩窗 + 热键 + 事件重设"即可成工具。

建议实现要点（按重要性）：

1. **常驻托盘 + 全局热键**（例如 `Win+Alt+L`）在 A/B 间切换；B 模式 = 主屏工作区 (0,0,960,1080) + 右半黑色遮罩；A 模式 = 恢复工作区 + 隐藏遮罩。
2. **遮罩窗属性**：无边框、`HWND_TOPMOST`、`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`，背景纯黑；覆盖范围用 `GetMonitorInfo` 的 `rcMonitor` 计算（外接屏右半），**不要写死 960**（适配 100% 缩放之外的场景）。
3. **工作区重设时机**：切换时设置一次，并监听 `WM_DISPLAYCHANGE`、`WM_SETTINGCHANGE`、`WM_DPICHANGED`、会话解锁/登录、任务栏变化，**重新应用**（否则会被 Explorer 按 KB4014104 重算覆盖）。
4. **让旧窗口立刻贴合**：对已最大化窗口做一次 `ShowWindow(SW_RESTORE)` + `SW_MAXIMIZE`（或 `SetWindowPos` 到工作区），否则它们会保持旧尺寸直到用户手动最大化。
5. **可选：把鼠标限制在左半**（`ClipCursor`），用热键开关；避免鼠标跑进看不见的区域。注意拖拽/游戏/远程桌面可能重置。
6. **可选：A 模式同时切分辨率**（如游戏时 1920×1080@260Hz、办公时 960×1080@60Hz）——但注意分辨率切换会闪烁且 960×1080 仍居中，**只在 PBP 方案下才需要**。
7. **不申请管理员权限**：`SPI_SETWORKAREA`、置顶窗、热键都不需要提权，降低使用门槛。

**与本仓库现有实现的对照**：根目录 `LeftScreenMode.ini` 已经提供 `LeftAreaPercent / CoverSide / Hotkey / MoveWindows / ResizeFullscreenWindows / ConstrainWorkArea / OverlayOpacity / OverlayColor / StartInLeftMode` 等配置，思路与上面一致；`LeftScreenMode.log` 记录的工作区 `0,0,960,1080` + 遮罩 `960,0,1920,1080` 说明该方案在 1920×1080 上已跑通。日志里出现 **`热键注册失败: Ctrl+Alt+L`**（13:01 与 13:02 两次），说明该组合可能被其他程序占用，建议改用 `Win+Alt+L`、`Ctrl+Shift+Alt+L` 等较少冲突的组合，并在注册失败时给出托盘提示/自动回退。

### 6.2 「软件遮罩 + 工作区」的真实体验与局限（必须提前知道）

**有效的场景**：浏览器、Office、资源管理器、聊天工具、IDE、终端等普通窗口；最大化；`Win+左/右` 贴靠（会贴到左半工作区内的左/右 1/4，行为与预期略有差异）；桌面图标（可用"显示桌面图标"整体关掉避免右半出现图标）。

**无效/有坑的场景**：

- **独占全屏游戏**：覆盖窗被绕过，游戏直接铺满 1920，右半内容被物理遮挡（看不见但仍在渲染）；这是软件方案的根本限制，微软 Q&A 也说明独占全屏下其他窗口无法显示，需改"无边框窗口"模式。([Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/5514066/how-would-i-put-an-application-like-a-clock-over-a)，访问日期 2026-11-03)
- **无边框全屏游戏/视频**：遮罩能盖住右半，但等于把画面右半切掉；视频最好改用"窗口 960×1080"或播放器裁剪/平移，或干脆用 A 模式。
- **任务栏**：Windows 11 任务栏固定在底部、不能移到侧边；右下角的时钟/托盘/通知横幅会落在被遮挡区。缓解：任务栏设为自动隐藏；用第三方任务栏/桌面时钟（Rainmeter、ElevenClock 等）放到左侧；或接受"看时间按 Win 看开始菜单/锁屏"。
- **通知**：Win11 通知固定右下角、不可改位置（微软 Q&A），B 模式下会被遮住；建议开"专注/勿扰"或接受。
- **鼠标**：默认仍可移入右半（看不见）；建议开 ClipCursor 或习惯用键盘。
- **Win+方向键贴靠**：贴靠以工作区为基准，左右贴靠会变成"左半里的左/右四分之一"，与 A 模式手感不同。
- **多屏场景**：工作区按"包含指定矩形的那台显示器"生效；如果同时开启笔记本内屏或再插一台屏，需要工具按显示器句柄分别处理，且遮罩只应盖外接屏右半；切屏/拔插后必须重算。
- **HDR**：如果开 HDR，纯黑遮罩窗在 HDR 合成下通常仍是黑，但个别驱动/色调映射下可能不是"绝对 0 nit"，需实测；最稳是 B 模式用 SDR。
- **安全桌面/锁屏/UAC**：遮罩窗不会出现在安全桌面，锁屏/UAC 切换瞬间右半可能闪一下桌面；不影响使用。
- **系统更新/驱动更新/远程桌面**：可能重置工作区或改变显示器枚举，工具需能自愈。
- **退出/崩溃**：工具异常退出时要保证遮罩窗和工作区被恢复（用 `try/finally` + 退出清理），否则会留下"右半永久黑"或"工作区只剩左半"的状态。

### 6.3 如果显示器支持 PBP：把它作为"游戏/视频模式 B"

- 若 4.6 确认显示器支持 PBP 且有第二路输入，则 **PBP 是唯一能让独占全屏游戏也待在左半的方案**：
  - 左半：笔记本 HDMI（正常桌面/游戏），源分辨率建议 960×1080（自定义模式）以填满左半不变形；
  - 右半：第二路输入喂黑场（笔记本 USB-C→HDMI 转接后输出纯黑桌面 / 闲置设备 / HDMI 黑场发生器）；
  - Windows 里把左半那块 960×1080 显示器设为主屏，窗口最大化、全屏游戏都会自然限制在左半。
- **代价**：PBP 通常锁 60Hz、失去 260Hz/VRR/HDR，需要多一根线/转接器，切换要动 OSD（2–5 秒）。适合"办公/看视频模式"，不适合高刷游戏。
- **切换策略**：日常用软件方案（6.1，快）；需要全屏游戏/视频时用 PBP（硬件级）；两者可共存：软件方案在 PBP 左半 960×1080 下无需遮罩（右半由显示器黑掉），只需切换 PBP 即可。

### 6.4 不推荐 / 无效的路线（避免浪费时间）

- **单独用分辨率切换**（QRes/DisplayChanger/NirCmd/CRU）：960×1080 会居中，左右各 480 黑边，不是左半。
- **显卡缩放 / Integer Scaling / DSR / VSR / Eyefinity**：原理上做不到；单屏 Eyefinity 不成立。
- **FancyZones / Divvy / AquaSnap 单独用**：只管拖放，不遮黑、不管最大化。
- **HDMI/DP 切换器**：只换信号源，不产生半屏。
- **期待 Windows 设置里"裁掉右半"**：没有这个功能（微软 Q&A 也确认无法让 Windows 只使用屏幕的一部分）。([Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/2779770/can-you-make-windows-10-not-display-a-part-of-a-sc)，访问日期 2026-11-03)

### 6.5 建议的最终组合（按用户情况排序）

1. **首选：自研轻量工具（工作区 + 黑色遮罩 + 热键）**——日常 A/B 一键切换，体验最接近"快捷"；本仓库 `src/Native.cs` 已是现成地基。若不想自研，可先用 AHK 脚本（约 100 行）验证效果。
2. **次选（愿付费、要任务栏/壁纸也按半屏管理）：DisplayFusion Pro**——Splits/Padding 约束最大化，右分屏设黑壁纸；但接受"右半不是绝对纯黑、全屏无效"。
3. **游戏/视频专用（若显示器支持 PBP）：PBP + 第二路黑信号**——唯一能约束独占全屏；接受 60Hz 和 OSD 切换。
4. **辅助**：QRes/DisplayChanger 做分辨率预设；ControlMyMonitor 做输入源/亮度快切；Dual Monitor Tools 的 Cursor 模块或 AHK ClipCursor 限制鼠标；任务栏自动隐藏 + 左侧桌面时钟解决时钟/通知问题。
5. **物理兜底**：右半贴哑光黑遮光板/黑绒布——保证"绝对纯黑、零漏光"，但不能替代布局约束（内容仍会渲染在右半）。

## 8. 本机可做的无风险验证清单（不改设置、不装软件）

1. 记下显示器型号（背面铭牌/Windows 设置 → 显示 → 高级显示），查说明书确认 PBP/PIP 与接口。
2. 用 `ControlMyMonitor /scomma`（如已安装）或显示器 OSD 查看是否有多画面选项与输入源切换项。
3. 在 Windows 设置里确认"缩放=100%、分辨率=1920×1080、刷新率=260Hz、主显示器=外接屏"。
4. 用 AHK/临时脚本试 5 分钟：只设工作区（不改分辨率），把记事本最大化，观察是否只占左半；再叠加一个黑色置顶窗验证"点击穿透/覆盖"效果，确认无残留后再考虑常驻。
5. 若考虑 PBP：先接第二路信号（USB-C 转 HDMI）做一次"两路同时显示"的测试，记录 PBP 下刷新率、右半无信号时的表现、是否影响 260Hz/VRR。
6. 记录 A/B 切换后需要重设的东西（任务栏、通知、鼠标、最大化窗口），作为工具需求清单。

> 备注：本文中涉及具体型号的 PBP 行为、PBP 下刷新率、OSD Position 是否可用等，均**因型号而异**；引用中标注"抓取受限/据检索摘要"的条目，建议用户以该型号官方说明书或实测为准。
